---
name: time-zsh-cd-hooks-without-shim-skew
description: "Use when measuring what a zsh cd/prompt hook (direnv, zoxide, mise hook-env, dev-profile-enter, portless) really costs; times each chpwd/precmd hook individually, avoids timing the mise shim instead of the real binary, and finds hung on-cd workers."
---

0. FIRST time every hook individually, don't guess. Write a script to a file (the Run tool refuses heredoc-to-file edits and `sleep`), then `zsh -ic 'source /tmp/x.zsh' </dev/null`. In it: `zmodload zsh/datetime; _zsh_deferred_init` (deferred hooks like direnv/zoxide/enter-converge only exist after this), `cd /tmp; cd <repo>`, then for each `$chpwd_functions` / `$precmd_functions` entry: `t0=$EPOCHREALTIME; $f; t1=$EPOCHREALTIME; printf` ms. A shell *builtin* `cd` can't be timed with `timeout 1 cd` (timeout can't exec builtins). Budget: blocking cd work <= ~100ms; anything else must be detached (`&!`).
1. Time the binary the hook actually calls, not the bare name. Tools on PATH are often mise shims (`command -v X` -> ~/.local/share/mise/shims/X -> mise) costing 0.5-0.9s per call. Read the hook's cached text (`~/.cache/zsh/init/<tool>.zsh`) to see the exact command it runs, then time that.
2. Known offender (2026-11): `__zoxide_hook` ran `\command zoxide add` in the foreground via the shim = 0.7-0.9s of every cd. Fix (dev-profile shell/zsh/40-zoxide.defer.zsh): redefine `__zoxide_hook() { \command zoxide add -- "$PWD" >/dev/null 2>&1 &! }`. User preference: KEEP the shim, just background it (hook call then costs 2-30ms). Don't pin real binary paths into cached init text unless asked; `z`/`zi` still pay the shim.
3. direnv hook cached text calls /opt/homebrew/bin/direnv directly (~9ms); `direnv export zsh` timed via bare name measured 0.5s only because of the shim. `mise hook-env -s zsh` ~0.14s idle (4 config reads + idiomatic-version lookups for tools in `idiomatic_version_file_enable_tools`), 0.3s+ while `mise dot watch` or stray `mise unuse --global ...` spin; check `ps -eo pid,pcpu,etime,command | rg 'mise (dot|unuse)'`. An invalid ~/.config/mise/config.toml (e.g. duplicate key from a concurrent agent edit) makes every mise call print a parse error and slows timing runs.
4. On-cd background worker: `~/.config/zsh/50-enter-converge.defer.zsh` forks `dev-profile-enter "$PWD"` for any dir with mise.toml/package.json. Look for hung workers: `ps -eo pid,ppid,stat,etime,command | rg 'dev-profile-enter|portless'`. A `portless proxy start` -> `sudo ... --port 443 --https` child with no tty sits stopped for minutes. Fixed in bin/dev-profile-enter (skip when `dev-profile-dev status` says unconfigured; `timeout 20 portless proxy start </dev/null`). bin/dev-profile-enter is hardlinked to ~/.local/share/dev-profile/bin/ (cp fails "same file"; editing may drop the exec bit: chmod +x).
5. Never print `ps -E` env output for a worker: it leaks secrets (ATASK_DB_URL). Filter with a fixed key list.
6. A fallback `omp -p` worker with cwd `/` and ppid 1 logging "Still starting after Ns" has no session file until startup finishes (check ~/.omp/agent/sessions/-/ and ~/.omp/logs/omp.<date>.<pid>.log). No session id means nothing for learn_from_transcript yet.
7. Landing shell changes in dev-profile: edits in the main checkout auto-fork to a worktree; use `wt switch -c <branch> --no-cd`, edit there (rebase first if the worktree predates main), `git commit -S` with a conventional subject (<=60 chars), then `wt merge -y main`. Commit hooks and wt merge can each take 3-5+ minutes on a loaded machine: run them with `background` and `wait`, never in a 300s foreground call, and check `git log` before retrying (the commit may have landed while only the merge timed out). Live apply: back up to ~/.local/state/dev-profile/backups/, `cp` repo shell/zsh/*.zsh to ~/.config/zsh/, delete ~/.cache/zsh/init/<tool>.zsh and open a `zsh -ic` twice to regenerate.
