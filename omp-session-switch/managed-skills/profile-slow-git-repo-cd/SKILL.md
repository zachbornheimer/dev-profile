---
name: profile-slow-git-repo-cd
description: "Use when cd into a repo is slow in zsh (starship/git prompt stalls, chpwd hooks, stuck mise/portless workers) or a stray \"Password:\" prompt appears after cd; covers timing git, hooks, hung background workers, and the sudo GUI askpass fix."
---

1. Resolve the real dir name first (user typos happen; ls the parent).
2. Time git first so you can rule it in or out: `time (timeout 60 git status --porcelain=v1 -uno | wc -l)`, `git ls-files | wc -l`, `git count-objects -v`. If it is tens of ms, git is NOT the cause; go to step 5.
3. Inventory zsh hooks with grep on ~/.config/zsh (chpwd|precmd|add-zsh-hook|direnv|zoxide|mise). Read the chpwd hooks. Measure a real cd: `zsh -ic 'zmodload zsh/datetime; s=$EPOCHREALTIME; cd <dir>; printf "%.3f\n" $((EPOCHREALTIME-s))'`. Note `*.defer.zsh` hooks (direnv, zoxide) only load on first line init, so -ic undercounts them; time `direnv export zsh` and `mise hook-env -s zsh` directly (direnv ~0.5s even with no .envrc).
4. Check for stuck workers: `ps -eo pid,ppid,etime,time,stat,command | rg 'dev-profile-enter|mise (unuse|deps|run)|portless|mise dot'`. Stat `T`/`TN` on `portless proxy start` -> `sudo ... --port 443 --https` = detached worker stopped waiting on a tty. This is also the source of a stray `Password:` on the prompt after cd (sudo reads /dev/tty, redirects do not help). `mise unuse --global X` with minutes of CPU = runaway contending with `mise dot watch`. Kill the stuck pids (SIGTERM), `launchctl kickstart -k gui/$(id -u)/dev.mise.mise-history` to restart dot watch. Do not kill an active `mise dot watch` fallback agent's work (atask fallback omp) without need.
5. The on-cd worker is `~/.local/share/dev-profile/bin/dev-profile-enter` (hardlink of dev-profile/bin/dev-profile-enter; the repo file is the source despite the "generated" header). It fires on any dir with mise.toml/package.json etc. Landed on main (584db32, 2026-11-09): exits when `dev-profile-dev status` says state=unconfigured; if nothing listens on 127.0.0.1:443 it runs `SUDO_ASKPASS=<osascript dialog script> sudo -A -v` (GUI password dialog), re-checks `sudo -n true`, then `timeout 20 portless proxy start </dev/null`; a cancelled dialog writes ~/.cache/dev-profile/enter/proxy-declined and skips the proxy for 60 min. Gotcha: a fix can sit on a side branch (09294b7 was only on chore/local-sync) — check `git branch --contains <sha>` before assuming it is live.
6. Editing the file: do it in a worktrunk worktree (`wt switch -c fix/<slug>`; wt takes ~25s, so `wait` on the promoted job). The edit tool drops the exec bit: `chmod +x` before committing. Commit with `git commit -S -m ... -- <path>`; the conventional-commit hook requires description <=60 chars. Then `wt merge -y main`; the installed hardlink updates itself.
7. If status hangs with ~0 CPU (ps stat U), trace: `GIT_OPTIONAL_LOCKS=0 GIT_TRACE2_PERF=/tmp/t2.log timeout 15 git status >/dev/null; tail /tmp/t2.log`. Known cause (oh-my-pi, 2026-11): partial clone left ~28.9k packs; fix `git repack -a -d --write-midx` (ask first).
8. Don't rm .git/index.lock while any git process runs. Avoid `sample` and raw `git worktree` (use `wt list`). Use rg, not grep -r. No `sleep` alongside other commands in run_command. Don't report machine load numbers unless asked.
