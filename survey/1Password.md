`apps/1Password` holds one file, `ssh/agent.toml`, which configures the 1Password SSH agent. It lists vaults rather than individual keys (Personal, Zysys, SAH, IIP Group, Clients, ZAB Ai, LLC), so any key added, rotated or re-imported into those vaults is served without a config edit. Order matters because `ssh` offers keys top to bottom; the comments tie that to the "too many authentication failures" problem and say deleting the file falls back to the Personal-vault-only default. `config/mise.toml` tracks `~/.config/1Password` with `mode = "track"` and `encrypt = true`.

No test or lint step targets this directory: nothing under `tests/`, `hk/` or `mise-tasks/` references it. The only checks are the repo-wide hk linters, which would see it as plain TOML, and the mise dotfile sync that places it on the machine. A bad vault name only shows up at runtime, when `ssh` fails to offer the expected key.
