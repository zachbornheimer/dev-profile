`apps/omp` is the source for oh-my-pi (omp) agent extensions and a daily-update timer. `extensions/` holds `run-agent-hooks.ts` (generated by `agent-hooks install omp`; maps omp events such as `tool_call` and `session_stop` onto agent-hooks events and reads `~/.config/agent-hooks/hooks.toml`), `herdr-omp-agent-state.ts` (herdr-managed state reporter), `machine-host-context.ts` (host context and status line) and `learn-command.ts` (the `/learn` workflow). Directories `hide-evidence`, `fallback-shake`, `gemini-filter-resume` and `thinking` hold further extensions. `hide-evidence` hides completion-gate `{"claim": ...}` evidence from the screen. `fallback-shake` shakes history after a model fallback. `gemini-filter-resume` retries after Gemini content-filter blocks (a "please continue" step, then a restated request, then stop). `thinking` provides `/thinking` and `/calm` display control. `omp-daily-sync.service` and `.timer` run `mise up github:zachbornheimer/oh-my-pi` daily at 05:00. `omp-daily-sync.plist` is a symlink to `com.zbornheimer.omp-daily-sync.plist`, which is not in the tree. `config/mise.toml` maps the extension files and the `fallback-shake`, `hide-evidence` and `thinking` directories, but not `gemini-filter-resume` (no mapping for it anywhere in the repo).

Tests are colocated `bun:test` files: `hide-evidence/hide.test.ts` (8 cases), `thinking/display.test.ts` (10), `gemini-filter-resume/rule.test.ts` (4), `fallback-shake/rule.test.ts` (2), `extensions/herdr-omp-agent-state.test.ts` (3) and `extensions/machine-host-context.test.ts` (3). The extensions with logic split a pure `rule.ts` or `display.ts` from the `index.ts` that touches omp APIs, and the tests cover the pure part. I found no repo CI or hk step that runs `bun test` on this directory. The three `index.ts` plugin shims and `run-agent-hooks.ts`, `learn-command.ts` have no tests here.
