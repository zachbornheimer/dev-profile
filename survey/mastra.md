`apps/mastra` holds one systemd user unit, `mastra-scheduler.service`, for the Mastra autonomous workflow scheduler (daily recursive-self-improvement and `optimize_tooling` twice a day). It sets `TZ=America/New_York`, because schedule rows carry a null timezone and the host clock is UTC. It runs from `/home/zbornheimer/Developer/Personal/capability-replicas/mastra`. `ExecStart` is a login-shell command that extends `PATH`, sources `~/.config/agent-state/env` and `~/.cache/ai/keys.env` if readable, sets `MASTRA_SCHEDULER=1`, and execs `bun scripts/loop/mastra-scheduler.mts`. It restarts always after 10 s.

No test or config entry covers it. Unlike the other apps, this directory is not listed in `config/mise.toml`, and no file under `tests/`, `hk/` or `mise-tasks/` mentions it, so nothing in the repo deploys or validates the unit. The paths in it are hardcoded to the `zbornheimer` home and to the sibling `capability-replicas` repository, so it only works on that host.
