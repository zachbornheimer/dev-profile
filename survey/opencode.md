`apps/opencode` is the OpenCode config tracked as `~/.config/opencode` (excluding `service.json`, `*.bak*` and `*backup*`). Config files: `opencode.json` (instructions from `~/.claude`, the skills path, and MCP servers: chrome-devtools, agentmux and MCP_DOCKER enabled; others disabled), `opencode.jsonc`, `tui.jsonc`, `cli.json` and `agent-hooks.json`. The last wires PreToolUse, PostToolUse, PreCompact and similar events to `AGENT_HOOKS_AGENT=opencode agent-hooks <Event>`, with 30 s timeouts. `plugins/` has `claude-hooks.js` (bridges the Claude Code hook scripts into OpenCode and runs the stop gate on `session.idle`), `herdr-agent-state.js` (herdr-managed), `worktrunk.ts` (branch activity markers for `wt list`, written for both OpenCode 1 and 2 plugin shapes) and `lib/stop-gate.js` and `lib/system.js` (the completion-gate bridge, capped at 3 consecutive blocks, and a process and home-dir facade meant to be stubbed in tests). `herdr-tui-session.js` and `herdr-opencode/tui.js` are herdr-installed TUI integrations. `agent/home-assistant-homelab.md` defines a Home Assistant agent. The directory also has a `package-lock.json` and two backups (`opencode.jsonc.hindsight-backup`, `agent-hooks.json.agent-hooks.bak`); the latter differs from the live file in its first hook event.

No tests are present in the directory, and no repo test or CI step references it. `plugins/lib/system.js` states the design intent (swap the module to stub processes and `$HOME`), but no stub tests ship. The herdr files carry "managed by herdr" headers and are overwritten on reinstall. Several files hardcode `/Users/zbornheimer` paths.
